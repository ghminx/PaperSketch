# 고정 참고 후보의 문자 수 기준 분할 결과

- 작성일: 2026-11-03임.
- 범위: 원본 auto와 동일한 ref.json 앞 200개를 미리 분할하여 저장함. 실제 검색 실행기와 프롬프트는 변경하지 않았음.
- 결과: 후보 텍스트 상한을 그룹당 800,000자로 설정하면 4개 그룹으로 분할됨.
- 저장 위치: `data/derived/MTPaperBananaBench/retrieval-first200-800k/`임.
- 기존 다운로드 데이터와 실행용 사본은 수정하지 않았으며, 모델·이미지 도구 호출은 0회임.

## 분할 기준

- 기준 데이터: `data/prepared/MTPaperBananaBench/ref.json`의 처음 200개임. 전체 ref 298개를 사용한 분할이 아님.
- 원본 순서를 유지하고, 후보 하나의 본문을 중간에서 자르지 않는 순차 분할임.
- 후보 ID·본문·캡션과 원본 후보 번호를 모두 보존함. 요약·내용 생략·키워드 추출을 수행하지 않았음.
- 각 그룹의 800,000자는 후보 블록만의 상한임. 실제 요청에는 선택 지침·사용자 방법론·캡션·host 포장 지시가 추가됨.
- 이전 CLI에서 관찰된 입력 한도 1,048,576자와의 차이인 최소 248,576자를 추가 입력 여유로 남긴 준비 기준임. 800,000자는 공식 제품 한도가 아니라 이번 분할을 위한 보수적 설정임.
- 문자 수는 UTF-8 디코딩 후 Python `len(str)` 기준임. byte 수나 모델 token 수와 다름.
- 실제 실행 시 완성된 요청 크기를 다시 검사할 필요가 있음. 이번 분할만으로 모델 context 수용이나 실제 응답 성공이 보장되지는 않음.

## 그룹별 선발 수에 따른 최종 비교 크기

- 아래 최대치는 각 그룹에서 본문이 가장 긴 후보 k개씩 뽑히는 경우의 후보 블록 문자 수 합계임.
- 관련성 선택 결과를 예측한 수치가 아니라 가능한 길이 조합의 상한임.
- 최종 비교에 후보 전문을 다시 입력하는 조건임. ID만 전달하는 조건이 아님.
- 최종 선택은 전체 선발 후보를 비교한 10개이며, 그룹별로 반드시 동일 수를 최종 채택하는 조건은 아님.

| 그룹당 선발 | 최종 비교 후보 수 | 후보 전문의 최대 문자 수 | 준비 기준인 후보 80만 자 이내 여부 |
|---|---:|---:|---|
| 3개 | 12 | 454,272 | 충족함 |
| 5개 | 20 | 651,205 | 충족함 |
| 6개 | 24 | 738,664 | 충족함 |
| 7개 | 28 | 819,518 | 초과 가능함 |
| 8개 | 32 | 898,029 | 초과 가능함 |
| 10개 | 40 | 1,049,902 | 초과 가능함. 후보만으로 관찰된 CLI 한도도 초과 가능함 |

- 7·8개 선발은 80만 자 준비 기준을 초과할 수 있지만, 그것만으로 실제 CLI 제한을 넘는다는 뜻은 아님. 완성 요청 크기로 판정할 필요가 있음.
- 제안: 현재 여유 예산을 유지한다면 그룹당 6개 → 총 24개 → 최종 10개를 우선 검토할 수 있음. 선발 수는 이번 작업에서 확정하지 않았음.
- 한계: 그룹당 6개 선발은 특정 그룹에 적절한 후보가 7개 이상 몰린 경우 일부를 조기 탈락시킬 수 있음. 200개 일괄 비교와 같은 선택 결과나 품질을 보장하지 않음.
- 그룹별 호출은 4회이며 최종 비교 1회를 더하면 Retriever 텍스트 호출은 총 5회가 되는 설계임. 아직 실행기에 연결하거나 실제 호출한 것은 아님.
