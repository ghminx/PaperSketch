**PaperBananaBench** is the benchmark introduced with
[PaperBanana: Automating Academic Illustration for AI Scientists](https://arxiv.org/abs/2601.23265)
(ICML 2026, spotlight). It evaluates how well a system can turn the text of a paper into a
publication-ready illustration. It has two tasks:

| Task | Input | Target | `test` | `ref` | Source |
|---|---|---|---|---|---|
| **Methodology diagram** (`diagram`) | method-section text + figure caption | human-drawn method diagram | 292 | 298 | NeurIPS 2025 papers |
| **Statistical plot** (`plot`) | tabular data (JSON) + short visual description | human-written plot (image + Matplotlib code) | 240 | 240 | repurposed from [ChartMimic](https://huggingface.co/datasets/ChartMimic/ChartMimic) |

The `test` split is for evaluation. The `ref` split is a disjoint reference pool that
PaperBanana's Retriever agent draws in-context examples from. Do not use `test` samples as
references.


## Dataset Details

### Methodology diagrams (`diagram`)

Built from NeurIPS 2025 papers (paper, Sec. 4.1):

1. **Collection and parsing.** 2,000 papers were randomly sampled from the 5,275 NeurIPS 2025
   publications. [MinerU](https://github.com/opendatalab/MinerU) extracted the methodology
   section text, all diagrams, and their captions.
2. **Filtering.** Papers without a methodology diagram were dropped (1,359 left). Diagrams were
   then kept only if their aspect ratio (w:h) was in [1.5, 2.5].
3. **Categorization.** Gemini-3-Pro assigned each diagram to one of four classes:
   *Agent & Reasoning*, *Vision & Perception*, *Generative & Learning*, *Science & Applications*.
4. **Human curation.** Annotators verified and corrected the method text and captions, checked
   the categories, and removed low-quality diagrams. The remaining samples were randomly split
   into `test` (292) and `ref` (298).

Test-set statistics: the source context averages **3,020.1** words and the caption **70.4** words
(recomputed from `diagram/test.json`, matching the paper).

### Statistical plots (`plot`)

Raw data behind published plots is rarely available, so the plot task repurposes
[ChartMimic](https://huggingface.co/datasets/ChartMimic/ChartMimic). ChartMimic pairs plots from
arXiv papers and Matplotlib galleries with human-written Python code. Gemini-3-Pro extracted the
underlying tabular data from the code and wrote a short description of each plot. After filtering
and sampling (paper, Appendix D), 240 test and 240 reference cases remain. They are stratified
across 7 categories and 2 difficulty levels.

| Category (`category`) | test | ref |
|---|---|---|
| `bar` | 40 | 40 |
| `line` | 40 | 40 |
| `scatter` | 40 | 40 |
| `tree_pie` | 40 | 40 |
| `misc` | 40 | 40 |
| `heatmap` | 20 | 20 |
| `radar` | 20 | 20 |

Difficulty (`difficulty`): test has 168 hard and 72 easy; ref has 160 hard and 80 easy.

## Dataset Structure

### Data fields: `diagram`

| Field | Type | Description |
|---|---|---|
| `id` | string | Sample id, e.g. `test_0`, `ref_1` (ids are not contiguous) |
| `split` | string | `test` or `ref` |
| `category` | string | One of the 4 diagram categories above |
| `content` | string | Methodology section text (Markdown, may contain LaTeX), extracted with MinerU and human-corrected |
| `visual_intent` | string | The original figure caption, used as the communicative intent |
| `image` | image | Ground-truth human-drawn diagram (JPEG) |
| `path_to_gt_image` | string | Relative image path inside the original zip (`images/<paper title>_diagram.jpg`) |
| `source_pdf` | string | File name of the source paper PDF (see [PaperBananaDiagramPDFs](https://huggingface.co/datasets/dwzhu/PaperBananaDiagramPDFs)) |
| `diagram_page_num` | int | Page of the PDF where the diagram appears |
| `method_section_title` | string | Title of the extracted method section |
| `width`, `height` | int | Pixel size of the ground-truth diagram |
| `rounded_ratio` | string | Aspect ratio bucket used as the generation target (`21:9`, `16:9`, `3:2`) |

### Data fields: `plot`

| Field | Type | Description |
|---|---|---|
| `id` | string | Sample id |
| `category` | string | One of the 7 plot categories above |
| `original_category` | string | ChartMimic's finer-grained category (e.g. `errorbar`, `PIP`, `quiver`, `3d`) |
| `difficulty` | string | `easy` or `hard` |
| `content` | string | JSON-encoded tabular data, e.g. `{"Year": [...], "Revenue": [...]}`. Use `json.loads` |
| `visual_intent` | string | Short natural-language description of the desired plot, including target figure size |
| `image` | image | Ground-truth plot (JPEG) |
| `path_to_gt_image` | string | Relative image path inside the original zip |
| `gt_code` | string | Ground-truth Matplotlib code (from ChartMimic) |
| `width`, `height` | float | Target figure size in inches (Matplotlib `figsize`) |
| `rounded_ratio` | string | Aspect ratio bucket |

## How to use

### With 🤗 Datasets (viewer-friendly parquet)

```python
from datasets import load_dataset
import json

diagrams = load_dataset("dwzhu/PaperBananaBench", "diagram")  # splits: test, ref
plots = load_dataset("dwzhu/PaperBananaBench", "plot")

ex = diagrams["test"][0]
ex["image"]          # PIL.Image of the human-drawn diagram
ex["content"]        # method section text
ex["visual_intent"]  # caption

table = json.loads(plots["test"][0]["content"])
```

### With the PaperBanana codebase (original layout)

The [GitHub code](https://github.com/dwzhu-pku/PaperBanana) reads the original zip layout. Download it and
unpack it under `data/`:

```bash
huggingface-cli download dwzhu/PaperBananaBench PaperBananaBench.zip --repo-type dataset --local-dir data
cd data && unzip PaperBananaBench.zip && cd ..
```

```
data/PaperBananaBench/
├── diagram/
│   ├── images/        # ground-truth diagrams
│   ├── test.json      # 292 samples
│   └── ref.json       # 298 samples (retrieval pool)
└── plot/
    ├── images/
    ├── test.json      # 240 samples
    └── ref.json       # 240 samples
```

In the JSON files, `additional_info` holds the per-task metadata that the parquet files expose
as top-level columns (`file_name`, `file_path`, `diagram_page_num`, `method_section_title`,
`width`, `height`, `rounded_ratio` for diagrams; `gt_code`, `width`, `height`, `rounded_ratio`
for plots).

The original PDFs of the diagram papers are in a separate repo,
[dwzhu/PaperBananaDiagramPDFs](https://huggingface.co/datasets/dwzhu/PaperBananaDiagramPDFs) (5.26 GB zip).

## Evaluation protocol

PaperBananaBench uses **referenced VLM-as-a-Judge** scoring (paper, Sec. 4.2). For each test
sample, a VLM judge sees the source text, the caption, the human diagram, and the generated
diagram. It decides **Model wins / Human wins / Tie** on each of four dimensions:

- **Faithfulness**: consistency with the method text and the caption.
- **Conciseness**: focuses on core information without visual clutter.
- **Readability**: intelligible layout, legible text, no excessive line crossings.
- **Aesthetics**: matches the stylistic norms of academic papers.

These outcomes map to 100 / 0 / 50. The **Overall** score is hierarchical. Faithfulness and
readability are primary: if they produce a decisive winner (it wins both, or wins one and ties
the other), that winner wins overall. Otherwise the same rule is applied to conciseness and
aesthetics. A score of 50 means parity with the human-drawn figure. The paper uses Gemini-3-Pro
as the judge. Agreement checks (Kendall's τ on 50 samples) are reported in Sec. 5.2.

Judge prompts are in [`prompts/diagram_eval_prompts.py`](https://github.com/dwzhu-pku/PaperBanana/blob/main/prompts/diagram_eval_prompts.py)
and [`prompts/plot_eval_prompts.py`](https://github.com/dwzhu-pku/PaperBanana/blob/main/prompts/plot_eval_prompts.py).
The scoring logic is in [`utils/eval_toolkits.py`](https://github.com/dwzhu-pku/PaperBanana/blob/main/utils/eval_toolkits.py). The full generation pipeline is run with
`main.py` (see the GitHub README for options).

## Notes on the parquet version

- The parquet files are built from `PaperBananaBench.zip` (kept in this repo for the GitHub code).
- In the zip, 9 diagram image filenames are mis-encoded, so their `path_to_gt_image` does not
  resolve (`test_65, test_81, test_149, test_205, test_269, test_281, ref_71, ref_284, ref_309`).
  The parquet files fix this, so every sample includes its image.
- `ref_1` has `split` corrected from `"re f"` to `"ref"` in the parquet files.
- Two diagram reference samples (`ref_260`, `ref_305`) have empty `content`.

## Intended use and limitations

- Intended for **research evaluation** of academic-illustration generation systems, and as a
  retrieval pool for in-context examples (`ref`).
- The diagram data comes from NeurIPS 2025 papers. It covers only AI/ML methodology diagrams
  with landscape aspect ratios (w:h in [1.5, 2.5]).
- VLM-as-a-Judge scores depend on the judge model. Report the judge you used.
- Diagrams and method text are reproduced from published papers, and copyright stays with their
  authors. If you are an author and want a sample removed, please open an issue on
  [GitHub](https://github.com/dwzhu-pku/PaperBanana/issues).
